# Deployments & Published Artifacts — the map

Single source of truth for **where pgStack lives**: what we publish to public
registries, what runs on the live VPS, and the pipelines that put it there.

> Posture note: the released **split** images (`pgstack-proxy` + `pgstack-postgres`,
> two containers) are the hardened production path — the proxy runs as a powerless
> role across a container boundary (SECURITY.md inv 22). The **all-in-one** and the
> demo/polyglot deployments below co-locate PG + proxy and are DEMO / SINGLE-TENANT.

---

## 1. Published artifacts (registries)

Cut by tagging `vX.Y.Z` → `release.yml` (runs on `ubuntu-latest`). Build-once /
promote-by-digest: the CI candidate builds + smokes + `sha-<commit>`-tags; the
release **promotes that exact digest** (no rebuild). Current: **v0.2.0**.

### Docker images — 4, multi-arch (amd64 + arm64)

| Image | Source | What it is |
|-------|--------|-----------|
| `pgstack-proxy` | `proxy-go/Dockerfile` | Go gateway: REST + auth + realtime WS + storage + edge functions; serves Studio/docs/landing |
| `pgstack-proxy-rust` | `proxy/Dockerfile` | Co-equal Rust sibling proxy (security parity) |
| `pgstack-postgres` | `Dockerfile.dev` | PostgreSQL 16 + pg_reactive extension (also tagged `16`) |
| `pgstack-all-in-one` | `docker/Dockerfile.all-in-one` | **DEMO/single-tenant** — PG + extension + proxy in ONE container |

- **Docker Hub** (public): `docker.io/pgstack/<image>` — tags `X.Y.Z` · `X.Y` · `latest` (postgres also `16`)
- **GHCR** (private): `ghcr.io/ndokutovich/<image>` — same tags + `sha-<commit>`

### npm (public)

| Package | What |
|---------|------|
| `@pgstack/sdk` | TypeScript SDK (live queries, REST, auth, realtime, DBOS) |
| `pgstack` | CLI — `npx pgstack init` |

> npm is published **without `--provenance`**: sigstore provenance requires a
> PUBLIC source repo and this repo is private (npm 422). `npm audit signatures`
> won't attest these. See SECURITY.md inv 23. Restore if the repo goes public.

### GitHub Releases

`github.com/ndokutovich/pg_reactive/releases` — one per `vX.Y.Z` tag.

## 2. Live environments (the VPS)

One VPS (`secrets.VPS_HOST`), deployed over SSH by `deploy.yml` on trusted master
push / dispatch (gated on green CI). PG data is ephemeral (recreated each deploy).
**The umbrella repo owns nothing but nginx routing** — all services live here; the
umbrella just maps domains → containers.

### A. Main app — `/opt/apps/pg-reactive-src`

`examples/docker-compose.yml` + `examples/docker-compose.prod.yml`. Services:
`db` (postgres+ext) · `proxy` (Go, serves the apex landing via `PUBLIC_DIR=/public`,
alias `pgstack-landing`) · `hello-go` (edge-function demo) · `web` · `inbucket` (dev SMTP).

| Domain | Serves |
|--------|--------|
| `pgstack.org` (apex) | landing page (`public/index.html` via proxy PUBLIC_DIR) |
| `reactive.pgstack.org` | the reactive demo app / proxy |

### B. Polyglot showcase — `/opt/apps/polyglot`

`deploy/templates/polyglot-showcase/docker-compose.yml`. Built on the VPS by
`apps/polyglot/build-all.sh` (8 images, tagged `:latest` locally — NOT the release
pipeline): the **all-in-one** (`pgstack/pgstack`) + 6 engines
(`polyglot-engine-{go,node,rust,fastapi,spring,dotnet}`) + `polyglot-generator` +
`polyglot-web` + shopping demo.

| Domain | Serves |
|--------|--------|
| `polyglot.pgstack.org` | polyglot showcase (one schema, 6 language engines) |
| `shop.pgstack.org` | shopping-vanilla demo |

## 3. Pipelines (how it gets there)

| Workflow | Trigger | Runner | Does |
|----------|---------|--------|------|
| `ci.yml` → `build-publish-images` | master push | **self-hosted** | build-once 4 multi-arch images, smoke each digest, create `sha-<commit>` tags |
| `release.yml` | `v*` tag | **ubuntu-latest** | promote `sha-<commit>` digests → version tags (GHCR + Docker Hub mirror); publish npm; GitHub Release |
| `deploy.yml` | master / dispatch | **self-hosted (the VPS)** | SSH deploy main app + polyglot showcase to the live VPS |

- Self-hosted runner = local Docker Desktop; network occasionally flakes on the
  heavy candidate build → just re-run. Release/deploy moved off it where possible.
- Supply-chain integrity (no-rebuild, digest-binding, tag-after-smoke, registry
  allowlist) is enforced by `tests/ci_supply_chain_test.mjs` (mutation-tested).

## 4. Accounts / secrets (where, not what)

- **npm**: org/scope `@pgstack`; NO secret — trusted publishing (OIDC), publisher = `ndokutovich/pg_reactive` + workflow `release.yml`, no environment, configured per package on npmjs.com.
- **Docker Hub**: account `pgstack`; `DOCKERHUB_USERNAME` + `DOCKERHUB_TOKEN`.
- **GHCR**: `GITHUB_TOKEN` (`packages: write`).
- **VPS**: `VPS_HOST` / `VPS_USER` / `VPS_SSH_KEY`; per-deploy secrets generated by `scripts/bootstrap-env.sh`.
