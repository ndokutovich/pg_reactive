pg_reactive

Subscribe to any SELECT query inside PostgreSQL.
Get JSON deltas pushed to your app when results change.
GROUP BY, window functions, JOINs, aggregates -- all reactive.

No extra process. No Kafka. No Materialize. No logical replication slots.
A single C extension loaded into Postgres. PostgreSQL-licensed.

$ cat ARCHITECTURE.md
How it works

pg_reactive installs as a C extension inside PostgreSQL.
No sidecar, no daemon, no external process.

  1. You register a query with pgr.subscribe(name, sql)
  2. pg_reactive attaches triggers to the underlying tables
  3. On INSERT/UPDATE/DELETE, it re-evaluates the query
  4. It diffs the previous and current result sets
  5. It emits only the changed rows as JSON via pg_notify

Supported constructs:
  + GROUP BY with aggregates (SUM, COUNT, AVG, etc.)
  + Window functions (ROW_NUMBER, RANK, LAG, LEAD)
  + Multi-table JOINs
  + Subqueries and CTEs
  + HAVING, DISTINCT, LIMIT with ORDER BY
  + Materialized view refresh triggers

Performance:
  Incremental evaluation -- not brute-force re-query.
  Typical delta latency: <5ms for tables under 10M rows.
  Memory: result sets are hashed, not stored in full.

$ cat EXAMPLES.md
Real-world subscriptions

-- Live dashboard: revenue by region
SELECT pgr.subscribe('dashboard', $$
  SELECT region, SUM(amount), COUNT(*)
  FROM orders WHERE status = 'paid'
  GROUP BY region
$$);

-- Real-time leaderboard with ranking
SELECT pgr.subscribe('leaderboard', $$
  SELECT user_id, score,
         RANK() OVER (ORDER BY score DESC) as rank
  FROM game_scores
  WHERE season = 'current'
$$);

-- Inventory alerts: items running low
SELECT pgr.subscribe('low_stock', $$
  SELECT sku, warehouse, quantity
  FROM inventory
  WHERE quantity < reorder_point
$$);

-- Multi-table join: user activity feed
SELECT pgr.subscribe('feed', $$
  SELECT u.name, a.action, a.target, a.created_at
  FROM activities a
  JOIN users u ON u.id = a.user_id
  WHERE a.created_at > now() - interval '1 hour'
  ORDER BY a.created_at DESC
  LIMIT 50
$$);
$ cat CLIENTS.md
Client integration

pg_reactive pushes deltas via PostgreSQL LISTEN/NOTIFY.
Any Postgres client library works. Zero vendor lock-in.

Node.js (pg)            -- client.on('notification', ...)
Python  (psycopg3)       -- conn.notifies()
Go      (pgx)            -- conn.WaitForNotification()
Rust    (tokio-postgres)  -- connection.notifications()
Elixir  (Postgrex)       -- Postgrex.Notifications
Ruby    (pg)             -- conn.wait_for_notify

Or use the optional pgr-ws WebSocket bridge:

  $ pgr-ws --port 8080 --db postgres://127.0.0.1/myapp

  ws://127.0.0.1:8080/subscribe/revenue_by_region
  // Deltas stream as JSON frames. Reconnects re-send current state.
