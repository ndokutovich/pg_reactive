pgStack · Live Examples

Seven concentrated lessons + two full apps. Each is the canonical "do it right" shape — no demo-only shortcuts, no patterns we'd later teach you to un-learn.

  • RLS first. Per-user data is gated at the row, not at the proxy.
  • Audience-bound subscriptions. query_id ≠ secret. JWT claims authorise the WS.
  • Server-derived ids. The client never invents a per-user query_id — a SECURITY DEFINER function does, from auth.uid().
  • Explicit grants. Each table grants only what its policies need.

Examples — concepts

1
Live Public Data
basic
Public live SELECT — the smallest pg_reactive can be. Useful for status pages, leaderboards, world tickers.
SELECT … FROM products WHERE in_stock
2
Joins + Aggregates
basic
LEFT JOIN, GROUP BY, HAVING, RANK() — pg_reactive computes the diff so subscribers never recompute.
RANK() OVER (PARTITION BY region)
3
Per-user Inventory
flagship
The deep authz pattern: SECURITY DEFINER binds query_id + audience to auth.uid(). Leak-proof channel names.
pgr.subscribe(…, '{"sub":"…"}'::jsonb)
4
RLS Shopping List
RLS
Multi-tenant: share lists by code. RLS gates the rows; per-member audience gates the WS. Both layers shown.
USING (member OR owner = auth.uid())
5
Notify vs Delta
mode
Same data, two subscriptions: one ships row deltas, the other just signals "something changed". Pick by your write rate.
pgr.subscribe(…, 'notify')
6
Presence + Broadcast
channel
Peer-to-peer chat with presence. Server wraps each broadcast as a typed envelope — peers cannot forge server deltas.
{"type":"broadcast","from":…,"payload":…}
7
Edge Function (http)
edge
A separate container in any language. Proxy injects X-Pgstack-Role/-Sub/-Claims; verify_jwt flag gates anon.
POST /functions/v1/hello-go
